# 경쟁 AI 테스트 도구 분석 요약

`harness/references/AI 테스트 툴 내부 동작.html`과 `harness/references/AI 테스트 툴 실제 화면.html`(팀 작성, 2026-11-10)을 정리했다. 대상은 Functionize, Mabl, testRigor, KaneAI, Testim, TestSprite, Pcloudy QPilot이다. 근거는 각 사의 공식 문서와 공개 화면이며 실제 계정으로 구동한 결과가 아니다. 마케팅 수치는 검증되지 않았다.

**용도:** 기능 범위와 화면 구성을 판단할 때 참고한다. 우리 화면 기준은 `harness/references/export/` 캡처이며, 이 자료는 ADR-012 우선순위에서 가장 낮다.

## 공통 엔진 루프

아래 번호는 HTML 원본의 표기다. SKRR 설계의 기준 번호는 `docs/architecture.md`의 "파이프라인 7단계"(①인식 ②생성 ③안정화 ④실행 ⑤치유 ⑥분석 ⑦보고)이므로, 문서나 대화에서 단계를 말할 때는 그쪽 번호를 쓴다. 두 표기 모두 ⑤는 치유이며 MVP에서 쓰지 않는다.

| 단계 | 내용 | 우리 설계 | 상태 |
|---|---|---|---|
| 진입 | 녹화, 평문, IDE 문장 | 자연어 요청 (UI-02-1) | 있음 |
| ① 해석 | 자연어 → 구체 스텝 | 시나리오 → TestQuery, 가드 검증 | 있음 |
| ② 로케이터 결정 | 스마트 로케이터, 자동 XPath | 카탈로그의 `data-testid`만 사용, 없으면 가드가 거부 | 치유 없음, 실패 분석에서 후보 제안 (ADR-015) |
| ③ 실행 | 브라우저, UI + API | Playwright, `apiRequest`, `waitForApi` | 있음 |
| ④ 스텝 관측 | 상태 + 스크린샷 | 단계 이벤트, 단계별 스크린샷, API 호출 기록 | 있음 |
| ⑤ 치유 | 의미 매칭으로 요소 재연결 | MVP 미포함. 결함을 가리지 않기 위해서 | ADR-015 |
| ⑥ 분석 | 결함과 불안정 테스트 분류, 원인 분석 | 원인 후보와 근거, 재현 3회 | 있음. 불안정 표시는 ADR-016 |
| ⑦ 리포트·환류 | 관리 도구, CI, 코드로 전달 | 리포트 화면, 이전 실행 대비 비교 | 외부 연동은 제외 범위 |

문서의 비교표는 팀 PoC(`agent/runner.py`) 기준이라 ⑥, ⑦을 "없음"으로 적었다. 이 저장소의 계약에는 원인 분석과 리포트가 이미 있다.

## 확인된 사실 중 설계에 영향을 준 것

| 사실 | 반영 |
|---|---|
| 모든 도구가 스텝마다 상태와 스크린샷을 남긴다 | 이미 설계에 있음 (`events.md`) |
| Mabl은 실행을 "Setup(API 시드·초기화) → 시나리오" 단계로 나눈다 | 케이스마다 초기화하는 순서와 일치 (`state-machines.md`) |
| TestSprite는 API를 실제로 호출해 본 응답으로 단언을 만든다 | 우리는 명세의 응답 스키마로 검사 (ADR-014). 명세가 없으면 `NOT_CHECKED` |
| Testim은 Flaky, Quarantine 개수를 대시보드에 보여 준다 | 재현 횟수로 불안정 표시 (ADR-016) |
| Pcloudy는 `{{key}}` 테스트 데이터 변수를 쓴다 | 같은 형식 사용 (TestQuery `variables`) |
| testRigor는 치유한 스텝에 `fixed-by-ai` 표시를 단다 | 치유를 도입한다면 같은 원칙으로 숨기지 않고 표시 (ADR-015) |
| 문서는 대상 사이트의 `/api/test/*` 격리를 차별점으로 든다 | `target-site-contract.md`의 테스트 전용 API 경로로 반영 |

## 공통 화면 골격 (참고)

좌측 메뉴(Home, New test, Results, Plans, Tests, Insights, Coverage, Settings), 실행 뷰(통과 막대, 통과 수, 치유 수, 단계별 대상), 스텝 편집기와 로케이터 패널, 치유 상세(Element history), 대시보드(통과율, Flaky, Quarantine), 페이지 플로우 맵.

우리 MVP 화면은 UI-01~UI-04로 정해져 있다. 대시보드, 커버리지, 플로우 맵은 캡처에 없으므로 만들지 않으며, 제안이 있으면 사용자에게 먼저 묻는다.

## 들이지 않는 것

| 기능 | 이유 |
|---|---|
| 녹화(Recorder) 방식 | 진입은 자연어 요청 (요구사항서) |
| 다중 브라우저, 실기기, 모바일 | 제외 범위 |
| Jira, CI 연동 | 제외 범위 (제품 기능으로서의 CI/CD) |
| 비주얼(베이스라인 이미지) 비교 | 제외 범위 (Vision AI 레이아웃 검사) |
