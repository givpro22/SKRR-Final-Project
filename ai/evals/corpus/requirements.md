# 목업 쇼핑몰 요구사항 명세서 (평가용 예제)

SKRR 팀이 평가용으로 만든 예제 문서다. 형식은 backend 템플릿(requirements_template.docx)과 같다: ID 줄, 설명, 수용 기준.

## 회원

FR-MEM-01 회원 로그인
설명: 회원은 이메일과 비밀번호로 로그인하고 액세스 토큰을 받는다.
수용 기준: 로그인 화면(login-submit-button)에서 올바른 계정이면 200과 토큰을, 틀리면 401과 "이메일 또는 비밀번호가 맞지 않아요" 안내를 보여 준다.

FR-MEM-02 회원 가입
설명: 비회원은 이메일, 비밀번호, 이름을 입력해 회원으로 가입한다.
수용 기준: 이미 가입한 이메일이면 409와 중복 안내를 보여 주고, 비밀번호는 8~20자만 허용한다.

## 상품

FR-PRD-01 상품 목록 조회
설명: 사용자는 카테고리별 상품 목록을 가격, 이름, 대표 이미지와 함께 본다.
수용 기준: 목록 화면(product-list)의 상품 수가 상품 목록 API의 개수와 같아야 한다.

FR-PRD-02 상품 상세 조회
설명: 사용자는 상품 상세 화면에서 가격, 재고, 설명을 확인한다.
수용 기준: 상세 화면의 가격(product-price)이 상품 상세 API와 DB의 가격과 같아야 한다. 없는 상품이면 404 안내를 보여 준다.

FR-SRCH-01 상품 검색
설명: 사용자는 검색어로 상품 이름을 검색한다.
수용 기준: 검색 결과(search-result-list)에는 검색어가 이름에 포함된 상품만 나온다. 검색어는 2~30자만 허용한다.

## 장바구니

FR-CART-01 장바구니 담기
설명: 회원은 상품 상세 화면에서 수량을 골라 장바구니에 담는다.
수용 기준: 담기 후 장바구니 화면(cart-item-quantity)과 장바구니 API, DB의 수량이 같아야 한다. 재고보다 많이 담으면 409 재고 부족 안내를 보여 준다.

FR-CART-02 장바구니 수량 변경
설명: 회원은 장바구니 화면에서 상품 수량을 바꾼다.
수용 기준: 수량은 1~99만 허용하고, 바꾸면 합계 금액을 즉시 다시 계산한다.

FR-CART-03 장바구니 상품 삭제
설명: 회원은 장바구니에서 상품을 하나씩 삭제한다.
수용 기준: 삭제 버튼(cart-remove-button)을 누르면 목록과 DB에서 해당 상품이 사라진다.

FR-CART-04 장바구니 합계 금액
설명: 장바구니 화면은 담긴 상품의 가격과 수량으로 합계 금액을 보여 준다.
수용 기준: 합계 금액(cart-total-amount)이 장바구니 API의 합계, DB의 가격×수량 합과 같아야 한다.

## 주문

FR-ORD-01 주문 결제
설명: 회원은 장바구니 상품으로 주문하고 결제한다.
수용 기준: 결제 화면의 합계 금액(order-total-amount)이 상품 금액 합계에서 쿠폰 할인을 뺀 값과 같아야 한다. 주문 번호는 서버가 부여한다.

FR-ORD-02 주문 내역 조회
설명: 회원은 자신의 주문 목록과 주문 상태를 본다.
수용 기준: 주문 내역 화면(order-history-list)의 주문 수와 상태가 주문 조회 API, DB와 같아야 한다.

FR-ORD-03 주문 취소
설명: 회원은 배송 전 주문을 취소한다.
수용 기준: 취소하면 주문 상태가 CANCELLED가 되고, 이미 배송이 시작된 주문은 409로 거부한다.

## 쿠폰

FR-CPN-01 쿠폰 목록 조회
설명: 회원은 보유한 쿠폰과 만료일을 본다.
수용 기준: 만료된 쿠폰은 목록에 나오지 않는다.

FR-CPN-02 쿠폰 적용
설명: 회원은 결제 화면에서 쿠폰 하나를 적용한다.
수용 기준: 최소 주문 금액보다 적으면 400과 "최소 주문 금액을 채워 주세요" 안내를 보여 주고, 적용하면 할인 금액만큼 합계가 줄어든다.

## 리뷰와 배송

FR-REV-01 상품 리뷰 작성
설명: 구매한 회원은 상품에 별점과 리뷰를 남긴다.
수용 기준: 별점은 1~5만 허용하고, 구매하지 않은 상품이면 403으로 거부한다.

FR-DLV-01 배송지 변경
설명: 회원은 주문 전에 배송지 주소와 연락처를 바꾼다.
수용 기준: 우편번호는 5자리 숫자만 허용한다.
